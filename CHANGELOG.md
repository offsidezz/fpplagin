# Changelog

Все заметные изменения плагина AutoCode. Версия задаётся константой `VERSION`
в начале `autocode.py`.

## [5.9.1] — 2026-06-18

Технический пасс: устранение гонок данных, утечек памяти и лишних IMAP-запросов.
Поведение для покупателя/продавца не меняется.

### Исправлено
- **Гонка при записи аренд.** Добавлен атомарный примитив `mutate_rentals(fn)`,
  который читает-меняет-пишет живой кэш аренд под общим `_rentals_lock`. Раньше
  шаблон `rentals()` → правка снапшота → `save_rentals()` позволял двум
  параллельным обработчикам перетереть изменения друг друга (выигрывал
  последний `save`). На атомарную запись переведены: лечение `chat_id`
  (`_heal`) и начисление бонуса за отзыв.
- **Утечка памяти в rate-limit.** `_check_rate` теперь выметает покупателей без
  активности за последний час, поэтому `_last_code_ts` / `_code_requests` не
  растут безгранично при долгом аптайме. Аналогичная чистка добавлена для
  `_PROBLEM_COOLDOWN`.

### Изменено
- **IMAP-выборка кода стала легче.** Окно по дате теперь уходит на сервер через
  `SINCE` (вместо `ALL` со сканом всего ящика). Сначала забираются только
  заголовки (`BODY.PEEK[HEADER.FIELDS …]`), полное тело тянется лишь для писем,
  прошедших фильтр по дате/теме. Используется `BODY.PEEK` вместо `RFC822`, так
  что письма больше **не помечаются прочитанными**. Есть мягкий фолбэк, если
  сервер не любит комбинированные критерии.
- **Кэш настроек.** `app_settings()` (горячий путь: `t()` на каждом сообщении,
  воркер IMAP-очереди) теперь читает из памяти и инвалидируется на
  `save_settings()`, а не парсит файл при каждом вызове. Вызывающим возвращается
  глубокая копия, так что правка результата не портит кэш.

### Удалено
- Мёртвый параметр `not_before_ts` у `fetch_code` (окно по дате теперь полностью
  задаётся `max_age_min`).
- Эжерное «лечение `chat_id` по имени покупателя на каждом сообщении» в
  `on_new_message`: оно дублировало tier-2/tier-3 ленивого лечения в
  `_find_active_rentals_for_chat`, делало полную запись снапшота на безобидных
  сообщениях и было незалоченной гонкой.

### Тесты
- 57 тестов (`pytest`), +7 новых: кэш настроек (инвалидация и изоляция копии),
  выметание stale-записей rate-limit, IMAP `SINCE`/`BODY.PEEK`/префетч
  заголовков и атомарность `mutate_rentals`.

### Известные дальнейшие шаги (вне этого PR)
- Запланированные рассылки и таймеры подтверждения/отзыва не переживают
  перезапуск (`threading.Timer` в памяти). Стоит вынести в персистентную
  очередь с восстановлением при старте — это отдельная фича, не быстрый фикс.

## [5.9.0]

Базовая версия в `main` до технического пасса 5.9.1.
