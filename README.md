# AutoCode — плагин автовыдачи кодов для FunPay

Плагин для [FunPay Cardinal](https://github.com/sidor0912/FunPayServer): автоматическая
выдача кодов/паролей из почты (IMAP) покупателям-арендаторам, учёт срока аренды,
стакание продлений, авто-бонусы за отзыв и учёт возвратов.

Единый файл — `autocode.py` (Cardinal-плагин). Текущая версия — см. `VERSION` в начале файла.

---

## Возможности

- **Автовыдача кода** по команде покупателя (`!cd`, `code`, `код`, `!код`). Код берётся
  из почтового ящика лота по IMAP, фильтруется по типу/длине, защищён от повторной выдачи.
- **Relay-источник (запрос у поставщика)**: вместо IMAP аккаунт может иметь `source = relay`
  с ником поставщика. По команде покупателя бот сам пишет поставщику в чат FunPay, ловит код
  из ответа и пересылает покупателю. Покупатель использует ту же команду `!cd`/`код`.
  Подробности — в разделе [Relay-источник](#relay-источник-запрос-кода-у-поставщика).
- **Учёт аренды**: срок считается от момента покупки; длительность берётся из названия
  лота (`24ч`, `30 дней`, `2 недели`, `1 месяц` и т.п.).
- **Стакание покупок (модель B2)**: несколько покупок одного покупателя на один
  почтовый аккаунт складываются в одно окно аренды (последовательное продление).
- **Скан при старте**: сканирует продажи за последний 31 день, восстанавливает/обновляет
  аренды (проставляет `buyer_id`, чинит `chat_id`, сливает дубли), чтобы `!cd` работал
  даже после перезапуска. Существующие сроки никогда не укорачиваются (ручные продления
  сохраняются).
- **Авто-продление за отзыв**: если в названии лота есть `+Nч за отзыв`, при оставлении
  покупателем отзыва аренда автоматически продлевается на N часов (один раз на заказ).
- **Запрос отзыва**: после выдачи кода бот просит оставить отзыв со ссылкой на заказ.
  Если отзыв по заказу уже есть — отправляется только код, без напоминания.
- **Учёт возвратов**: при возврате заказа (live-событие или скан при старте) его часы
  вычитаются из аренды; если возвращены все заказы — аренда удаляется. Идемпотентно.
- **Уведомления об истечении**: предупреждение за 12 часов и сообщение о завершении аренды.
- **Лояльность**: бонусные дни постоянным покупателям при повторной покупке в окне лояльности.
- **IMAP health-check**: проверка всех почтовых аккаунтов при старте и периодически;
  алерт в Telegram при недоступности почты.
- **Резервные копии** `rentals.json` (ротация).
- **Telegram-панель**: настройки текстов, аккаунтов почты, статистика, активные аренды.
- **Команды покупателя**: `!time`/`время` — остаток аренды, `!продлить` — ссылка на
  продление, `!faq`/`команды` — справка.

## Установка

1. Скопировать `autocode.py` в папку `plugins/` вашего Cardinal.
2. Перезапустить Cardinal. Плагин подхватится автоматически (точки входа
   `BIND_TO_*` в конце файла).
3. Настроить почтовые аккаунты и тексты через Telegram-панель бота.

## Формат названия лота

Длительность аренды парсится из названия лота. Поддерживаются (рус/eng):

| Период  | Примеры в названии                  |
|---------|-------------------------------------|
| Часы    | `24ч`, `12 часов`, `6h`             |
| Дни     | `1 день`, `30 дней`, `7d`, `сутки`  |
| Недели  | `1 неделя`, `2 недели`, `1 week`    |
| Месяцы  | `1 месяц`, `3 месяца`, `1 month`    |
| Годы    | `1 год`, `1 year`                   |

Бонус за отзыв указывается отдельно и **не** считается в основную длительность:
`NETFLIX 30 ДНЕЙ / 720ч • +12ч ЗА ОТЗЫВ` → аренда 720ч, +12ч при отзыве.

> Если длительность в названии не найдена — аренда **не создаётся** (см. предупреждение
> в логах). Добавьте период в название лота.

## Relay-источник (запрос кода у поставщика)

Если вы перепродаёте доступы и не держите почту сами, аккаунту можно задать
`source = relay`: коды запрашиваются у **поставщика** (продавца, у которого вы
покупаете) прямо в чате FunPay.

**Как работает:**

1. Покупатель пишет в чате заказа `!cd` / `код` — обычная команда.
2. Бот видит, что лот привязан к relay-аккаунту, и отправляет поставщику текст
   запроса (поле «Текст запроса», поддерживает `{lot_id}` и `{order_id}`).
3. Поставщик отвечает сообщением с кодом.
4. Бот извлекает код и пересылает покупателю (`🔑 Ваш код: <код>`).

**Настройки relay-аккаунта (Telegram `/autocode` → Аккаунты):**

- **Поставщик** — ник продавца на FunPay (нужна хотя бы одна переписка с ним,
  чтобы у вашего аккаунта существовал чат — обычно она уже есть после покупки).
- **Лоты / Категории** — к каким заказам применять relay.
- **Текст запроса** — что отправить поставщику.
- **Длина кода** — `4/5/6/7/8`: бот возьмёт из ответа ровно столько идущих подряд
  цифр (защита от ложных чисел). `0`/«авто» — любое число 4–8 цифр.
- **Regex** — продвинутый разбор (группа 1 = код); если задан, имеет приоритет над длиной.
- **Нет в наличии** — список стоп-фраз поставщика; при совпадении покупателю уходит
  уведомление, а вам — сигнал в Telegram. «-» отключает детекцию.
- **Авто-напоминание** — через сколько секунд повторно пнуть молчащего поставщика
  (`0` — выкл).
- **Отзыв/подтверждение** — включать ли запрос отзыва после relay-выдачи.
- **Таймаут** — сколько ждать ответ поставщика (по умолчанию 180с).

**Подбор покупателя.** Если у одного поставщика одновременно ждут несколько
покупателей, код по умолчанию уходит по очереди (FIFO). Если в ответе поставщика
есть номер заказа/лота — код адресно уходит именно этому покупателю. Номер заказа,
если поставщик его «эхо-нул», не путается с кодом.

## Хранение данных

В `storage/autocode/` (JSON):

- `rentals.json` — активные аренды (ключ — `order_id`). Поля включают `buyer`,
  `buyer_id`, `chat_id`, `email`, `lot_id`, `lot_name`, `order_ids`, `orders`
  (детализация по заказам), `review_bonus`, `expires_at`, `hours`.
- `used_codes.json` — уже выданные коды (защита от повторов).
- прочие: логи выдач, состояние предупреждений, health, языковой кэш.

## Архитектура (кратко)

- `on_new_order` — создаёт/продлевает аренду при покупке.
- `on_new_message` — обрабатывает команды покупателя, выдаёт коды, начисляет бонус за отзыв.
- `on_order_status_changed` — обрабатывает возвраты.
- `_startup_sales_scan` — скан продаж при старте (стак B2 + сверка + вычет возвратов).
- `_expiry_watcher` — предупреждения за 12ч и завершение аренды.
- `_imap_health_worker` / `_startup_imap_test` — мониторинг почты.
- `_imap_queue` — очередь IMAP-запросов с защитой от гонок и повторной выдачи.
